Why do we store 34 and divide by 100 instead of directly building 0.34?

        The Real Reason

        When parsing "12.34" from a string, we only see characters:

        '1' '2' '.' '3' '4'

        Characters don't contain floating-point information.

        So we must reconstruct the number mathematically.

        Mathematical Representation
        12.34

        is actually:

        12 + 3/10 + 4/100

        Which can be rewritten as:

        12 + 34/100

        That is exactly what the code does.

        Why We Store 34

        Because the digits after the decimal:

        "34"

        are just an integer sequence.

        So we convert them normally:

        34

        Then scale it:

        34 / 100 = 0.34
        Firmware Engineer Mental Model

        Think of the decimal point as a scaling factor.

        digits_after_decimal / 10^number_of_digits

        Example:

        Input	Fraction	Divisor
        0.5	5	10
        0.25	25	100
        0.375	375	1000
        Why This Approach Is Powerful

        This same technique works for:

        string → float

        string → fixed-point numbers

        sensor data parsing

        protocol decoding

        And it avoids expensive functions like:

        atof()
        strtod()
        sscanf()
        One Embedded Insight (Very Important)

        In many microcontrollers we don't even use float.

        Instead we store:

        12.34  → 1234

        and remember:

        scale = 100

        This is called fixed-point arithmetic and is widely used in firmware.

        Example:

        temperature = 2534
        means
        25.34 °C

Now let's fix A2 (This is a very powerful concept)

You said you weren't sure why this works:

result = result * base + digit;

This works because of positional number systems.

Every number system follows this rule.

Decimal Example (base 10)

Number:

123

Mathematically:

1×10² + 2×10¹ + 3×10⁰

Now watch what the algorithm does.

Start:

result = 0
First digit (1)
result = 0 * 10 + 1
result = 1
Second digit (2)
result = 1 * 10 + 2
result = 12
Third digit (3)
result = 12 * 10 + 3
result = 123

You just reconstructed:

1×10² + 2×10¹ + 3×10⁰

without explicitly computing powers.

Binary Example (base 2)

Binary:

1011

Math:

1×2³ + 0×2² + 1×2¹ + 1×2⁰

Now apply the same algorithm.

Start:

result = 0
First digit (1)
result = 0 * 2 + 1
result = 1
Second digit (0)
result = 1 * 2 + 0
result = 2
Third digit (1)
result = 2 * 2 + 1
result = 5
Fourth digit (1)
result = 5 * 2 + 1
result = 11

Which is correct:

1011₂ = 11₁₀
Why This Is So Powerful

Because every positional number system follows the same rule:

digit × base^position

The algorithm simply builds the powers automatically.

Instead of computing:

10²
10¹
10⁰

we do:

multiply by base each step
Firmware Engineer Insight

This one line:

result = result * base + digit;

can parse any number system:

Base	Number
2	binary
8	octal
10	decimal
16	hex
36	alphanumeric

Example:

"1A" in hex
result = 0*16 + 1 = 1
result = 1*16 + 10 = 26
Why This Is Important for Embedded Engineers

This exact algorithm is used in:

UART command parsing

protocol decoding

hex register parsing

bootloaders

shell interpreters

Many firmware systems implement their own parsers using this idea.
